# Voltra Standalone — Android APK

This is a **self-contained Android application**, not an HTML shortcut to a hosted dashboard. It bundles the Voltra responsive device cards and all advanced settings locally, communicates with devices through Android's Wi-Fi network, and does **not** need a Node.js server, login, account, cloud or MatterBridge.

## Installing

- Get the Preview APK from [GitHub Releases](https://github.com/aYmAn-Helmy/voltra-standalone/releases/tag/android-preview-v0.1.0). Choose the APK asset.
- Android **8.0 (API 26)** or newer. Enable installation from your browser/files app when Android asks.
- Connect the phone to the **same private Wi-Fi network** as the MTTL-W01 Standalone firmware devices.
- Launch the app. It scans the current **/24 IPv4 LAN segment** automatically, confirms `/api/status` returns a real device MAC and `/api/device` has four channels, then saves verified sources.
- Tap **⌁ فحص Wi-Fi** to rescan, or enter a device IP manually if the router uses guest-network isolation, VLAN routing or a nonstandard subnet.

## Features

The existing Voltra UI, source cards and advanced device panel are bundled in the APK:

- Physical strip IP discovery; persist devices by MAC and update IP after a rescan
- Four outputs plus all-on/off control
- Wattage, voltage, energy (Wh), current, temperature, RSSI, uptime, firmware, Wi-Fi and protection data
- Native `/api/events` SSE stream per device, immediate relay + metering updates, in-memory graph and browser events, 30-second HTTP status fallback
- Device/outlet renaming, physical-button locks, countdown timers, 8 scheduler rules, protection thresholds, MQTT/HA, Wi-Fi scan/connection and FWR firmware upload with strict checksum validation
- Standalone firmware's original dashboard via external browser, if necessary

**SSE limitation:** The MTTL-W01 embedded firmware allows only **one SSE listener**. The Android app opens at most one per strip and reconnects with backoff; if the strip's own dashboard is already open, readings temporarily use the HTTP fallback.

**Scope:** Current auto-discovery scans one private /24 IPv4 network. It does not search other router VLANs, guest segments or IPv6. Devices must use the compatible [af950833/mttl_w01_standalone](https://github.com/af950833/mttl_w01_standalone) firmware; stock or unsupported firmware may not expose the required endpoints. Home Assistant or other MatterBridge instances are not auto-discovered.

## Security

The device's firmware only exposes plain HTTP on the LAN. Android connects to the physical strip IP using native HttpURLConnection bound to the Wi-Fi network and **rejects non-private IPs and redirects**. The HTML interface is served entirely from APK assets using `https://appassets.androidplatform.net/` (virtual WebView origin), and external links open in the system browser. No credentials or device config are sent to a Voltra-hosted server.

Changing Wi-Fi can move the strip to a new IP or disconnect it. Firmware OTA can render the appliance unusable, and must only be used with a known-compatible .fwr and independently obtained release SHA-256, stable power and local recovery ability.

## Build from source

```bash
cd android
gradle :app:assembleDebug
```

The GitHub Actions workflow `.github/workflows/android-apk.yml` builds a sideloadable **debug-signed Preview APK** and attaches it to a prerelease. Debug signing certificates generated by different CI runs may change, so subsequent previews may require uninstall/reinstall before upgrading. This is not a Play Store production-signed release.

Build uses Android Gradle Plugin 8.7.3, Gradle 8.10.2, Java 17 and compileSdk 35. Android Java sources are under `android/app/src/main/java/com/voltra/standalone`; the existing Voltra web UI is reused directly from `public/`.

## Verification

GitHub Actions confirms that the Android sources compile to an APK. Network and firmware behavior in this first Preview have **not yet been verified on real hardware or an Android device**; test discovery and simple output control on one accessible strip before using power scheduling, Wi-Fi changes or OTA.
