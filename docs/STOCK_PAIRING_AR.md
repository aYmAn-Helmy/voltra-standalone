# تشغيل المشترك الرسمي (Stock Firmware) على PowerA

PowerA Hub دلوقتي عنده مستقبل أصلي لبروتوكول MTTL-W01 على **TCP 10086**، وبيتحكم في المشترك الرسمي **من غير سيرفر powerk إضافي**.

## ليه المشترك الرسمي مش بيظهر بالـ Wi-Fi Scan؟

- الـStandalone بيقدم HTTP API، وبالتالي PowerA يقدر يتصل بيه مباشرة باستخدام الـIP.
- الـStock العادي **هو اللي بيتصل بالسيرفر**، مش العكس؛ في الفيرموير الأصلي عنوان سيرفر محفوظ داخل المشترك.
- لازم عنوان السيرفر المحفوظ يكون هو **IP جهاز PowerA Hub** والمنفذ ثابت **TCP 10086**.
- اكتشاف PowerA APK للـHub على المنفذ **8098** شيء مختلف تمامًا عن اتصال المشترك الرسمي بالسيرفر.

## 1. إعداد PowerA Hub

شغل PowerA Hub على كمبيوتر أو Raspberry Pi ثابت الاتصال بنفس شبكة المنزل. لو موجود ملف إعدادات قديم `powera/config.json`، استبدل مصدر `stock-home` (اللي كان بيطلب powerk على 8080) بالمصدر ده مع الاحتفاظ بمداخل Standalone:

```json
{
  "sources": [
    { "id": "stock-native", "type": "stock-native", "name": "المشتركات الرسمية" },
    { "id": "standalone-office", "type": "standalone", "name": "المكتب",
      "url": "http://192.168.1.55", "mac": "00:11:22:33:44:55" }
  ]
}
```

**مهم:** IP وMAC الخاصين بالـStandalone في المثال للتوضيح فقط، استبدلهم بالقيم الفعلية. ولو معندكش Standalone، احذف السطر الخاص بيه تمامًا. النسخة الجديدة من `powera/config.example.json` فيها مصدر Stock مباشر افتراضيًا.

أوقف تشغيل `powerk.py serve` لو شغال على نفس الجهاز، لأنه بيشغل TCP 10086 هو كمان، ومينفعش السيرفرين يمسكوا نفس المنفذ.

```bash
python3 -m powera.hub --config powera/config.json --db powera/data.sqlite3
```

المفروض يظهر في الطرفية إن مستقبل Stock شغال على TCP 10086. افتح الداشبورد على `http://IP-OF-HUB:8098` من نفس الشبكة. في Linux تقدر تتأكد من المنفذ عن طريق `ss -lntp | grep 10086`. على Windows جرّب `netstat -ano | findstr :10086`.

## 2. التهيئة الأولى للمشترك الرسمي (مرة واحدة)

الخطوة دي مش بحث تلقائي. لازم تدخل المشترك في وضع **SoftAP** وتوجهه إلى IP جهاز PowerA Hub.

1. هات عنوان الـIPv4 المحلي للكمبيوتر اللي عليه Hub (مثال: `192.168.1.14`). لو الكمبيوتر IP بيتغير، ثبّته من DHCP Reservation في الراوتر.
2. اضغط زر المشترك الرئيسي حوالي 10 ثوانٍ علشان يدخل وضع الإعداد ويبدأ مؤشر الـLED يومض بسرعة.
3. من كمبيوتر أو تليفون عليه Python ومتصل Wi-Fi، اتصل بشبكة المشترك `TONLY_TAP_XXXXXXX`، وكلمة مرورها عادةً `LGU_XXXXXXX` بنفس سبع حروف الملحقة باسم الشبكة حسب توثيق powerk. تأكد من تفاصيل جهازك.
4. نفّذ الأمر من جذر مشروع PowerA على **الجهاز المتصل بشبكة المشترك المؤقتة**:

```bash
python3 -m powera.stock_bridge provision --ip 192.168.1.14 --ssid "HOME_WIFI_2.4G"
```

الأمر هيطلب باسورد شبكة البيت تفاعليًا (مش مكتوب في سطر الأوامر). IP اللي بعد `--ip` لازم يكون **IP جهاز الـHub**، مش `192.168.1.1` بتاع شبكة إعداد المشترك، ومش IP الجهاز اللي بينفذ التهيئة لو مختلف عنه.

الرد المتوقع:

```text
up:ip:ip_ok
up:connect:connect_ok
```

5. ارجع لشبكة البيت. المشترك هيحاول الاتصال بـPowerA على `IP-OF-HUB:10086` ويظهر تحت **Stock** بعد الاتصال والـgetinfo.

لو عندك مشتركات أصلًا موجهة لنفس IP جهاز الـHub، غالبًا مش هتحتاج تعيد التهيئة؛ أوقف powerk وشغّل PowerA TCP 10086 على نفس العنوان.

## 3. لو المشترك لسه مش ظاهر

- من الداشبورد راقب رسالة **مستقبل Stock TCP 10086**: هل شغال وهل المتصلين صفر؟
- اتأكد إن الجدار الناري سامح باتصالات **TCP 10086 و8098 داخل شبكة المنزل الخاصة فقط**، مش من الإنترنت.
- المشترك لازم يكون على **Wi-Fi 2.4GHz**، والراوتر ما يكونش مفعّل Client Isolation.
- Hub ومشترك Stock لازم يقدروا يوصلوا لبعض، وإن عنوان IP المخزن في المشترك ما اتغيرش.
- لو المنفذ 10086 محجوز من powerk القديم، أوقفه. PowerA هيعرض خطأ عند التشغيل بدل ما يدّعي إنه بيسمع للمشترك.
- اختبارات البروتوكول في المشروع بتشتغل مع **محاكي TCP**، ولسه محتاجين نجرب على فيرموير Stock حقيقي قبل ما نعتبر التوافق مضمون.

## تحذير

النسخة الحالية بدون توكن أو حسابات بناءً على طلب التطوير، وبالتالي **أي جهاز موثوق أو غير موثوق على الشبكة المحلية المسموح لها قد يقدر يتحكم في الكهرباء**. ما تفتحش بورت 10086 أو 8098 من الراوتر للإنترنت، ومتستخدمش شبكة ضيوف أو شبكة عامة. التحكم البرمجي مش بديل لحماية الكهرباء الفيزيائية.
